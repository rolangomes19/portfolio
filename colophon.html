How this site is built

The footer says this site is WCAG 2.2 AA and RTL-ready, and every component runs on design tokens instead of hand-picked values. Those are claims a design-system review should be able to check, not take on faith. This page is that check: the actual token count, the actual fonts and why each one is here, the actual accessibility testing performed, and the actual before/after numbers from the performance pass — sourced from this repo's own architecture notes and cleanup log, not written up separately from them.

Tokens, not values

83 custom properties in css/tokens.css — colour, type, the Carbon-style spacing scale (--space-01 through --space-12), radius, shadow, duration, and easing. Light theme lives on :root; dark theme is one [data-theme="dark"] block overriding the same property names, never a second set of rules. css/styles.css — every component in the site — has zero raw colour values except two, and both are deliberate: a physical printed photo (.work-card-media, .about-photo) doesn't turn dark just because the page theme did, so those two fills are pinned regardless of theme, documented in place. Zero !important anywhere in the file.

Six fonts, each with a job

All self-hosted, nothing served from a third-party font CDN.

Inter
Body text. Self-hosted from rsms.me/inter/.
Commissioner
Headings and buttons.
Geist Mono
Eyebrows, meta labels, code — the monospace voice that marks this site's own system to itself, like the one on this page.
El Messiri
RTL headings and buttons, substituting for Commissioner under [dir="rtl"].
Harmattan
RTL body, mono, and eyebrow text, substituting for Inter and Geist Mono under [dir="rtl"].
Caveat
Sticky-note handwriting only — the small annotation text on the photo captions and stat cards, never body copy.

The first three are Latin-subsetted; Caveat was instanced to a static weight and subsetted too, once it turned out to be shipping unsubsetted and unpreloaded (see the performance numbers below). Both changes are covered in this repo's own docs/FONT-LOADING-PERF-PLAN.md and docs/CLEANUP-PLAN.md.

Accessibility, measured

Verified live in a browser, not inferred from the markup:

  • Contrast. Zero WCAG AA failures across every text node on the homepage, in both themes, across all eleven mat-colour swatches — including the one colour with no pre-solved lookup table entry, which clears AA on its own through a live binary-search derivation (see js/main.js §4b).
  • Touch targets. No interactive element under 24×24 CSS px at a 320px viewport.
  • Reflow. No horizontal overflow at 320px, in either reading direction.
  • Motion. Every transition and animation in styles.css routes through three duration tokens; prefers-reduced-motion: reduce collapses all three to 1ms in one rule, not a per-component opt-out.
  • Keyboard and structure. One h1 per page, no skipped heading levels, no duplicate IDs, a skip link as the first focusable element, and a visible focus ring on every interactive element — including inside the surface-recolour panel's own radiogroup, which supports arrow-key selection like a native <input type="radio">.

Built for both directions

css/styles.css contains zero physical left/right properties — no margin-left, no text-align: left, no border-right. Every layout rule uses logical properties (margin-inline-start, inset-inline-end, text-align: start) so flipping dir="rtl" mirrors the entire layout without a single direction-specific override. Directional icons carry an .icon-directional class that flips them under [dir="rtl"] — the arrow on this very page's site-logo link is one of them. Numbers, phone numbers, and email addresses stay left-to-right inside right-to-left text via <bdi> wrapping, so a UAE phone number doesn't get its digit order reversed by the bidi algorithm.

What got measured and fixed

This site went through its own cleanup pass — the same kind of audit its case studies describe doing for other products. Before/after numbers, not estimates:

  • 89%

    Cut from the site's heaviest images (7.07MB → 0.79MB across 7 files) — three were base64-encoded PNGs wearing an SVG file extension, re-encoded as WebP at the resolution they're actually displayed at; four were genuine vector diagrams that just needed path-precision cleanup, not rasterising.

  • 85%

    Cut from the favicon (124KB → 18KB) by reducing an auto-traced illustration's coordinate precision to what a 16–32px icon can actually show — verified pixel-identical to the original at both render sizes before shipping.

  • 61%

    Cut from tokens.css (82KB → 31.7KB raw) by moving two inline SVG data URIs — the light and dark cutting-mat illustrations — to external, separately-cacheable files once neither turned out to depend on a CSS custom property.

  • 72%

    Cut from four of this site's pages' JavaScript payload (285KB → 78.6KB raw) by splitting page-specific translation content out of the shared script, so a page with no case-study body stops downloading one anyway.

No build step

Plain HTML, CSS, and vanilla JavaScript. No framework, no npm dependency, no bundler in the path between editing a file and it being the deployed site — what's in this repository is what a browser reads. The handful of command-line tools used to prepare assets above (svgo for path precision, fonttools/pyftsubset for font subsetting, sharp for the image re-encodes) ran once each, by hand, to produce a smaller committed file — none of them run again on a visitor's request, and none of them are a dependency of the site itself.
