Discovery

The violations surfaced mid-migration, not from a routine audit: as the Hub platform moved through the Bootstrap v3.3 → v5.2 upgrade and an Enhanced Data Model rollout, a full accessibility pass found 35 issues — 8 Critical, 27 Serious — spread across the portal's most-used surfaces.

Triage

Critical issues went first — the ones that blocked task completion outright for assistive-technology users — then Serious issues were grouped by pattern rather than fixed one-by-one, since most traced back to a handful of repeated components rather than 27 unrelated bugs. That grouping is what made a live-migration timeline survivable: fixing the pattern once fixed every instance of it.

Fix methodology

Six patterns accounted for nearly all of it: focus states, clickable affordances, modal alignment, filter behavior, loaders, and drawer interactions. Each was standardized once — for example, focus rings moved from inconsistent or missing outlines to a single token-linked treatment applied everywhere a focusable element exists — rather than patched per page.

Detailed documentation for this section is in progress.

Re-test

Re-tested across QA and pre-PROD environments after the fixes shipped, confirming zero Critical or Serious issues remained.

Zero state — and staying there

The same six patterns are now documented inside the Blueprint Design System itself — focus rings, ARIA, and keyboard behavior are built into the component library's base states (see the Blueprint Design System case study), not left to be re-implemented correctly by whoever touches a page next. The fix is structural, not a one-time cleanup.
